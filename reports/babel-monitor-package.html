On-node storage (maximize under RAM budget)

Constraints

  • Target RSS ~≤1MB; hard ceiling 2MB
  • No flash for metrics — rings in RAM only
  • Flash/UCI: package config only (CLI/GUI-driven) — never metrics
  • Fixed preallocated structures; no unbounded growth

Packing strategy

  • Compact binary sample records in RAM (fixed-width integers)
  • Node-level aggregates on configurable sample_interval (CLI -interval; default 10s; range 5–300)
  • Size ring to use the budget: aim for ≥24h at default 10s if it fits in ~1MB
  • Live -interval changes the timer; ring capacity fixed (retention hours scale with interval)
  • Event ring ~512; live neighbor snapshot for UI / api=live

Sample fields (schema 2)

  • t, seq; neighbor/route counts; mean/min LQ; mean cost; bad_cost_count; add/remove deltas
  • Link: tx_packets/retries/fail deltas; optional SNR/bitrate
  • DNS/arednlink deltas; babel hard/soft reset deltas; lqm_ok / babel_ok
  • Host: uptime_s, reboot_delta; mem_total_kb / mem_available_kb / mem_used_pct; cpu_pct (interval) + cpu_peak_pct (1s peak)

Identity

  • node_id = mesh IPv4 (primary poller key)
  • meta / hello also returns MAC and hostname — first connect or on demand, not every sync
  • Sync samples carry node_id + boot_id + seq; central caches MAC/hostname from last hello
  • Wire format: JSON + optional gzip L1

Sync API (pull-only, multi-server)

EndpointPurpose
?api=meta (alias hello)node_id (mesh IPv4), mac, hostname, boot_id, schema, retention, compress_default
?api=sync&since_seq=N&limit=MSamples seq > N for current boot_id, paged JSON
?api=sync&since_t=T&limit=MBy timestamp (since_seq preferred)
?api=events&since_seq=NEvent ring
?api=liveCurrent neighbors + latest sample

Transfer compression

Optional · default on · low CPU Compress wire responses only (not in-RAM rings). Use gzip / zlib level 1 via built-in ucode-mod-zlib. Accept compress=1|0 or on|off (case-insensitive) via UCI, query, or CLI -compress. Skip compression for tiny responses (<~1KB).
Gap-tolerant contract Always HTTP 200 when daemon is up. Include truncated, gap_before, next_seq/next_t, complete, boot_id. Empty samples with truncated=true is success. No per-server state on the node.

Example poller script

Workstation/central prototype at contrib/babel-monitor/tools/babel-monitor-poller (not required on the node APK).

CommandBehavior
hello <node>First-connect: GET meta; print node_id, MAC, hostname, boot_id; update state
pull <node>Incremental sync via saved cursor; append to local log; advance state on success
status <node>Show local cursor / hello fields / log path
-hHelp

Per-node state keeps since_seq so repeat pulls only fetch new data. On boot_id change: reset cursor, note gap, refresh hello.
