aredn-traceroute hostname resolution

Review of how hop display names are filled when traceroute omits a hostname, and AREDN-backed enhancements that could close gaps.

contrib/aredn-traceroute 0.1.15 resolveDisplayHostname
Verdict Current logic already covers the three best live sources: traceroute name, hop sysinfo, and previous-hop LQM (with mesh-hostname refresh for tunnel IPs). The highest-value gaps are a local arednlink IP→name index (no extra fetches) and optional next-hop LQM look-back (needs buffering or a second pass).

Current pipeline

Stock traceroute runs first; enrichment is sequential. Type/cost use previous-hop LQM; path metric uses local Babel host routes. Name resolution reuses the same sysinfo/LQM cache.

Important follow-on in enrichHop

After a mesh name is learned (especially from previous LQM), if the hop was only fetched by numeric traceroute IP, enrichment re-fetches http://{name}/a/sysinfo?lqm=1 and rebinds the cache entry. That improves later LQM lookups and can upgrade the displayed name to sysinfo’s node field. Unreachable hops (* * *) are not named or enriched.

Why names still go missing

Tunnel / WG hop IPs

Traceroute shows 172.31.x (or similar). Sysinfo on that IP often fails or returns an LQM that does not index the next hop until refreshed via mesh hostname.

Prev LQM miss

findNeighbor only matches tracker.ip / canonical_ip / hostname. If the ICMP address is not those fields, previous-hop naming fails even when the node is known elsewhere.

No local reverse index

Failed sysinfo is cached with no retry. mesh.getNodeList is used for destination metric IP only — not as an IP→name fallback for hop display names.

Enhancement ideas

IdeaEffortValueApproachLimitation
Local arednlink reverse map (IP → name)LowHigh Build IP→nodename from /var/run/arednlink/hosts. Zero network I/O; helps when traceroute IP equals a published mesh/dtdlink/lan IP. Does not name pure tunnel endpoint IPs unless published in hosts.
Next-hop LQM look-backMediumHigh When hop N+1 sysinfo is available, findNeighbor(N+1, hopN.ip) for hostname of N. Streaming prints hop N before N+1 exists; needs one-hop buffer, two-pass, or late rewrite.
CLI destination name for final hopLowMedium If last hop IP matches resolved dest IP, use the user-supplied destination name. Only helps the last hop.
Broader arednlink / /etc/hosts aliasesLowMedium Match hop IP against dtdlink.*, lan.*, xlink* lines. May be interface aliases, not the callsign users expect.
DNS / resolveip on hop IPLowLow–Med Optional reverse or hosts lookup via mesh DNS for 10.x. PTR often absent; 172.31 WG endpoints rarely reverse-resolve.
Scan any cached LQM (not only prev)LowMedium If hop M’s trackers mention hop N’s IP, use that hostname. Usually redundant with prev.
Babel host routes as name sourcen/aNone alone Routes give dst IP + metric + nexthop LL — no hostname. Keep for metrics only.

Recommended order if implementing

1. Local arednlink IP → name

Extend or mirror mesh.getNodeList() with a reverse index over arednlink host files. Call it from resolveDisplayHostname before declaring unresolved.

2. Destination name for final hop

If hop IP equals resolved dest IP (already computed for Babel Metric), prefer the CLI/CGI destination label.

3. Next-hop look-back (if streaming allows)

Buffer one hop before printing, or run a lightweight second pass over cached sysinfo only.

Not worth chasing alone Babel dump-installed-routes and babel.getNeighbors() do not carry AREDN hostnames (IPv6 LL + interface). Keep them for metrics/cost only.
